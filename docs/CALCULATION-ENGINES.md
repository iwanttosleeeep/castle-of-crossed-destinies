## 时间约定

- 输入是 **当地出生证明上的公历钟表日期/时间**，精度到分钟。范围 1900–2099；需要时刻的体系不接受未知时间，不自动填正午。只选数秘 / Dreamspell 时允许仅填日期，不搜城市、不构造虚假的 UTC 瞬间。
- 城市选择来自固定 geonamescache 3.0.1 数据；用城市中心经纬度和 IANA zone。小城市未收录可选择附近城市，但边界盘需注意坐标误差。本版没有强行假设所有出生地都是 UTC+8。
- IANA 数据固定为 tzdata 2025.2，并显式从该包加载，避免主机与 Docker 的时区版本不一致。未来时区政策可能变化；升级需重新跑历史测试。
- 夏令时跳跃造成的不存在时间拒绝排盘；重复时间要求用户选择较早或较晚一次。不得静默猜测。
- 西占、印占、Human Design 始终用 UTC 瞬间；数秘和 Dreamspell 用原始当地公历日期；八字和紫微的日时默认用当地标准时（扣除历史 DST），或用户选择真太阳时（经度差 + 均时差）。
- 八字年/月柱按绝对时刻转换到 UTC+8 后读取 lunar-javascript 的节气历表；日/时柱按用户选择的当地标准/真太阳时读取。避免将海外民用时间误当北京节气时刻。
- 午夜/子初换日显式传给引擎。底层 lunar-javascript 的晚子时干规则沿用其实现；不同传统对晚子时的分歧不被包装为唯一答案。
- 紫微使用 iztro default、农历正月初一年界、fixLeap=true、晚子进日或不进日对应设置；不把它的农历月四柱当成八字节气四柱。
- 每次请求启动独立 Node 子进程，避免 iztro 的全局流派配置串入另一位访客；同一 Python worker 最多两个并行子进程、排队两秒、计算二十秒超时。

## 西占约定

地心视位置、日期真黄道、热带黄道。Astronomy Engine 目标误差约 1 角分；显示 0.001° 不表示数据具有该精度。ASC 用黄道与几何地平交线的东侧点，MC 用子午线交点；不加大气折射。整宫宫位从 ASC 所在星座起算，不把 MC 硬塞进第十宫。

北纬/南纬绝对值 66°及以上暂不输出 ASC/MC/宫位，保留行星与相位，等待独立高纬用例验证。
合/刑/拱/冲容许度 6°，六合 4°；只比较十天体，未区分入相出相。
运动方向按前后各一小时的黄经变化判断；近停滞阈值 0.005°/天。

## 印占约定与精度

采用 NatalEngine 的 `calculateLahiriAyanamsa` 近似公式（J2000 值 23.856944°）及 rashi/nakshatra/大运常量，不调用其整套 `calculateVedic`。天体位置由 MIT 的 Astronomy Engine 路径提供，减去岁差值后得到恒星黄经；ASC 同样减岁差，宫位为整宫。D9 星座由恒星黄经 ×9 mod360 得到，不能把 D1 宫位当成 D9 宫位。

月交点默认采用平均交点多项式，也可选择 hd-chart-engine 的真交点轨道法近似；Rahu/Ketu 始终相差 180°。这不是 Swiss Ephemeris 的逐位等同实现。未注明 ayanamsa 的外部报告只能作近似比对，不应宣称完全一致。距 D9/宿足边界 0.05°内会提示复核。

Vimshottari 仅计算九个 Mahadasha，首运按月亮在宿内的实际剩余比例，固定岁长 365.25 日，连续累计而非四舍五入到月份。日期字符串的毫秒位只用于可复现；月亮黄经的细小差异可能放大为数日运限差异，不宜据此精确预测事件。高纬度限制同西占，不输出 Lagna 或宫位。

## Human Design 约定与选择理由

采用 [hd-chart-engine](https://github.com/domalhambra/hd-chart-engine) 默认 MIT / Astronomy Engine 路径：地心热带视位置、轨道法近似真月交点。通过太阳黄经回溯 **88°** 的根求解寻找 Design UTC，不是减去 88 天。闸门轮起点为 223.25°，每闸门 5.625°、每爻 0.9375°。只保留 gate/line，细分字段不传给解释模型。

NatalEngine 只提供 gate/center/channel 表。Castle 按完整通道建立中心图，计算连通分组、马达至喉中心的连接、类型和权威优先级；不采用其整套 Human Design 计算器、人物解说或生物学因果叙述。已定义、未定义但有激活、完全开放中心分开记录。交叉仅给四闸门，不猜名称。

距爻线边界 1′内提示出生记录/外部盘复核；这是提醒带宽，不是经过认证的误差上界。没有宣称色/调/基或四箭头达到可用精度。hd-chart-engine 的可选 GPL `ephemeris` / `moshier` 模块未安装或导入。

## 数秘与 Dreamspell

数秘采用 [Numerology.com 的分段日期缩减](https://www.numerology.com/articles/your-numerology-chart/life-path-number-meanings/)：月、日、年分别缩减，各阶段保留 11/22/33，再合计缩减。姓名可选，只接受用户确认的 A–Z 拼写（允许空格、连字符和撇号）；A–Z 循环映射 1–9，全名直接求和后缩减，不先缩减每个词。元音默认 AEIOU，Y 可显式切换。没有元音或辅音时对应字段是「未计算」，不是数值 0。不自动将中文/其他文字转写为拉丁字母。

Dreamspell 按 [Law of Time 年/月表](https://www.lawoftime.org/pdfs/OvertoneMoon.pdf)本地实现：2004 年基数 52，平年每年推进 365，月偏移忽略 2/29；归一化到 Kin 1–260，调性 `(kin−1)%13+1`、图腾 `(kin−1)%20+1`。这是现代 Dreamspell，不是传统 Maya Tzolk’in 的连续计日。

[官方解码说明](https://lawoftime.org/decode/)将 2/29 视为特殊日，生日午前建议用 2/28、午后用 3/1。Castle 对该生日强制要求用户明确选择映射，不悄悄归到另一日，并保存实际换算日期。即使没有时间也能选择；不把真太阳时或 UTC 日期偷偷套入日期型体系。

## 数据流与隐私

出生资料 → 后端校验/历史时区 → 本地 Node → 所选 1–7 套事实 → 用户确认 → 原有轻量 Skill / DeepSeek 报告 → Tribunal / 庭审。

`POST /cases/calculate` 不接收也不需要模型密钥。计算完成才创建案件；错误不会生成空案。
出生输入、坐标、UTC、DST、引擎版本、依赖锁文件 SHA-256、太阳时修正记录保存在 `calculation` 字段；确认事实可编辑，原计算记录保持不变。恢复与 Markdown 导出带上这些信息。它们属于敏感资料，不应分享恢复令牌或公开案卷。

后续 AI 仅接收各室事实，并不读取其他体系；这不意味着出生信息完全不会到达模型——盘面事实含计算用日时等必要数据。只有确认后才发送给 DeepSeek。
可选姓名仅进入数秘事实，不传给其他密室；未选数秘时服务端丢弃姓名参数。填写姓名会把它连同算法过程保存在数秘事实和计算来源中，确认后也会发送给数秘解读模型。

## 当前验证与未验证

- 八字样本四柱与提供的盘面一致；紫微十二宫主星、命身宫与四化的关键字段回归。
- J2000 十天体、ASC/MC 与 [OpenFate 公开的 Swiss Ephemeris 基准](https://openfate.ai/en/editorial-methodology/calculation-validation)交叉对照（位置阈值 0.02°，角度阈值 0.002°）。这是一组基准，不是全日期认证。
- 2024 立春前后、海外同瞬间节气一致、真太阳时跨日、晚子换日、历史中国夏令时、美国 DST gap/fold、并行隔离、缺依赖错误。
- Human Design：用户授权的本地 Maia Mechanics / Jovian Archive 样本 26 个 gate.line、类型/权威/Profile/定义一致；无姓名/地名的测试夹具；另测九类组合、悬挂闸门、多个分组、1900–2099 年中的 20 个季节日期太阳弧残差。不公开源 PDF。
- 印占：J2000 天体与选定岁差的计算一致性、参考样本 D1/D9 星座/宿足、交点选项、120 年大运连续性。参考报告未注明 ayanamsa，仅用 0.03° 月亮黄经容差，不要求运限日期完全一致。
- Dreamspell：官方表中的四个日期样例以及参考 Kin 133、闰日两种显式映射；数秘：日期分段主数、姓名数、Y、无姓名/无元音/无辅音、不支持文字拒绝。
- 七套事实有界且无缺失值，服务器时区变更不影响四套新增算法；日期-only 案件可保存/导出，姓名不跨室；七室恢复/确认/报告（模拟 AI）链路回归。
- 真实 Node 计算接入案件，恢复、确认、Markdown 导出及 AI runner 的事实隔离测试；测试 AI 文本调用用 mock，不消耗用户 Key。
- 尚需更多独立历书/天文基准，尤其早期历史时区、闰月紫微、不同流派和边界分钟。接入并通过这些回归不等于已覆盖所有异常盘。
